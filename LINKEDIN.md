# Sharing AegisGrid (e.g. LinkedIn, UK)

Use this page when you promote the repo. Keep claims **accurate** — that protects you and sets the right expectations for readers.

## One-line pitch

**Free, MIT-licensed open source for local IoT refrigeration gateways** — access control, temperature safety bounds, audit logs, and file integrity checks, with **no cloud AI required**.

## Suggested LinkedIn post (copy and edit)

I've published **AegisGrid** on GitHub — **free under the MIT Licence**, no signup or paid tier.

It's a **reference project** for teams who need **offline-first** patterns on small refrigeration/IoT gateways: hashed operator tokens, DuckDB audit/threat cache, 1°C–8°C software watchdog modelling, and signed manifest checks with rollback if files are tampered with.

**Why I'm sharing it:** Useful building blocks shouldn't be locked behind expensive platforms. This is for learning, adaptation, and community review — **not** a certified safety product.

## What **not** to claim

| Avoid | Say instead |
|--------|-------------|
| "Unhackable" / "stops all hackers" | "Raises the bar for **local** control and audit" |
| "Production-certified safety" | "Reference implementation; needs hardware interlocks + professional validation" |
| "Registered trademark ®" | "Open-source project name" (unless you have registered it) |

**Company names and trade marks are different.** Before heavy branding, search the [UK IPO trade mark register](https://www.trademarks.ipo.gov.uk/ipo-tmcase) and [EUIPO TMview](https://www.tmdn.org/tmview/) for similar marks. This document is **not legal advice**.

## Security expectations (honest)

Publishing open source can attract curiosity from researchers and opportunistic scanning — that is normal. You are **not** claiming a magic shield; you are sharing **documented, testable** code (`pytest` in the repo) for others to review and harden.
